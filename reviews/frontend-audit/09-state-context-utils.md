## Cross-cutting patterns
- **Context value instability (4 providers)**: all of Auth, Subscription, RoleSecurity and Theme build an un-memoized `value`. Combined with UI state stored in AuthContext, any small toggle re-renders the whole tree (36 `useAuth` consumers). Fix all four with `useMemo`/`useCallback` and move non-auth UI state to Zustand.
- **Client-trusted authorization or ownership (3)**: localStorage role simulation (RoleSecurityContext), reachability-as-verification (domainsSlice), and a localStorage-only rate limiter (rateLimiter). Gate simulation on the real claim, and let the server own verification and limits.
- **Optimistic sync layer is half-wired (4 defects)**: retries never escalate, rollback is unreachable, insert/preferences/audits rollback is a no-op, and `retryCount` is mutated in place. The layer needs one redesign rather than piecemeal fixes; consider TanStack Query mutations or a single `executeMongoMutation` retry path with a collection→state-key map.
- **Fabricated seed data as initial state (4 slices plus the telemetry store)**: domains, goals, alerts and HUD logs/score ("98.4/100"). Combined with the "replace only if non-empty" sync, real users see fake data. Use empty state plus a `hydrated` flag.
- **Unvalidated external data (3)**: `/api/state/sync` JSON, `/api/analytics/*`, and localStorage (`catalystlab_local_session`, the rate-limit counter). Add Zod at the boundary. Only ThemeContext and the role-simulation key validate their stored values.
- **Dark-only pastel colour classes in shared config (2 utils, ~40 class strings)**: `rolePermissions.ts` and `cardUtils.ts` export `text-*-300/400` colours with no light-mode pair. Every consumer inherits the failure on the light-first canvas. Centralise them as theme-aware badge tokens.
- **Async races without cancellation (3)**: analytics stats, realtime pulse, and the subscription refresh on user change. Use request ids or AbortController.
