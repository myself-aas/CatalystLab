## Cross-cutting patterns
- **Server modules inside `src/lib` (8 files):** analyticsEngine, emailService, networkSecurity, nodeEngines, securityAudit, serverAuth, webhookSecurity, webhookService, plus blogLoader. One of them has already leaked into the browser (blogLoader, Critical). Move them to `server/lib/` and add an ESLint `no-restricted-imports` rule that blocks `fs`/`mongodb`/`firebase-admin`/`tls`/`dns` under `src/` (excluding the server folder).
- **Unvalidated persisted or remote data:** 15 Firestore `as` casts and 6 localStorage `JSON.parse` readers in firebase.ts, plus `res.json()` results used unchecked (api keys, trial, contact). One Zod schema set in `src/types` would cover all of them.
- **Mock or simulated values presented as real:** analyticsEngine fallbacks (8 metrics), firebase audit-log derivation and seeds, and monitored-site, API-key and blog seeds. Add an explicit `simulated` flag everywhere.
- **localStorage caches not scoped by user:** reports, GitHub repos, GitHub events and inquiries (4 keys). Scope each key by uid and clear them on logout.
- **Silent swallow (`catch {}` / "Ignored error"):** about 20 sites in firebase.ts, and `setLogLevel('silent')` hides Firestore errors. Several of these hide real failures (deleteReport, Firestore init).
