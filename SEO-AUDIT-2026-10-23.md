# SEO Audit: catalystlab.tech

Date: 2026-10-23
Scope: production build of `catalystlab@2.4.0` (`dist/`, 74 HTML files, 61 prerendered routes, 13 application routes), served locally on `node dist/server.cjs` for header, status-code and compression checks.
Crawl source: the build output itself, not a live crawl. See "Not measured" at the end.

---

## Executive summary

**Overall health: 55/100. The architecture is good. The delivery to crawlers is not.**

This site has an unusually solid technical foundation for a React app of its size: 61 prerendered routes, a distinct title and description on every one of them, self-referencing canonicals on the `www` host, a sitemap that matches the prerendered set exactly, a real 404 page with a 404 status, `noindex` on every application and auth route, HSTS, and a CSP with per-build hashes. That work is done and it is correct.

Then the crawler opens the `<body>`. Every one of the 74 HTML files contains 566 bytes of body markup: a `<noscript>` block and an empty `<div id="root">`. There are zero `<a>` elements in the HTML. The only `<h1>` on the page is "JavaScript is required". The prerender pipeline generated the `<head>` for 61 routes and never generated the document. For Googlebot this is frictional rather than fatal, because Google renders JavaScript on a deferred second pass. For Bing, most AI crawlers, every social unfurler, and every tool that reads raw HTML, the site is 61 empty pages with well-written metadata.

The second problem is a one-line bug with a large cost. `server/app.ts:63` compresses `text/html`, `text/css`, `text/plain`, `application/javascript` and five others, but not `text/javascript`, which is the content type Express 5 now sends for `.js`. HTML and CSS arrive gzipped. Every JavaScript file arrives raw. The homepage pulls 18 bundles on first paint: 1712 KB raw versus 533 KB gzipped. **1178 KB of avoidable transfer on every first visit, on every route.** That is the cheapest LCP and INP win available on this site and it is a five-character edit.

Third: the sitemap advertises pages that no crawler can read, and the URL space accepts unlimited paths that return 200 with the homepage shell and the homepage canonical. Content is being published into a hole: 10 finished blog posts sit in `src/data/engineBlogs.ts`, none are prerendered, none are in the sitemap, and all of them canonicalise to `/`.

### Top five issues

1. **No server-rendered content.** 74 files, 0 links, 1 placeholder H1, 566-byte body. (Critical)
2. **JavaScript served uncompressed.** 1178 KB per first paint from a missing MIME type. (Critical)
3. **Soft 404s at scale.** Unknown `/blogs/*`, `/reports/*`, `/playground/*`, `/developer/api` and `/design-system` return 200 with the homepage title and canonical; and Cloudflare `_redirects` widens the set to `/docs/*`, `/dashboard/*`, `/admin/*`. (High)
4. **The blog is invisible.** 10 seeded posts plus Firestore posts, zero in the sitemap, canonical pointing home. (High)
5. **16 duplicate indexable URLs.** `/engines` = `/hub` = `/services`, `/products` = `/plugins` = `/integrations`, `/blogs` = `/insights`, `/reports` = `/report`, plus six `/docs` pairs, each with its own self-canonical. (High)

### Quick wins, in order of return per hour

| # | Change | Effort | Expected effect |
|---|---|---|---|
| 1 | Add `text\/javascript` to `COMPRESSIBLE_CONTENT_TYPE_RE` (`server/app.ts:63`) | 5 min | 1178 KB less transfer on first paint |
| 2 | `noindex` the six duplicate alias routes and drop them from the sitemap | 30 min | Removes self-inflicted cannibalisation |
| 3 | Return 404 for unknown `/blogs/*`, `/reports/*`, `/playground/*` slugs; stop rewriting `/docs/*` in `_redirects` | 1 hr | Closes the soft-404 surface |
| 4 | Rewrite the homepage H1 to the query the product answers | 30 min | Strongest on-page signal currently says nothing |
| 5 | Prerender the 10 seeded blog posts and add them to the sitemap | 2 to 3 hrs | Turns a dead channel into 10 indexable pages |

## Technical SEO findings

### T1. Every public page ships an empty body

**Issue.** The prerender step injects per-route `<head>` metadata but not per-route content. Rendered HTML for all 61 public routes is `<noscript>` plus `<div id="root"></div>`.

**Impact.** High.

**Evidence.** Measured across all 74 HTML files in `dist/`:

```
<pricing/index.html>
  title: "Pricing — CatalystLab"            canonical: .../pricing        robots: index, follow
  body bytes: 566
  <a> elements: 0
  <h1> elements: 1  →  "JavaScript is required"
```

Identical body on `/`, `/pricing`, `/docs`, `/compare`, `/terms`, `/engines` and the other 55. No anchor text, no headings, no paragraphs, no image `alt` attributes reach a non-rendering crawler.

**Fix.** Render each public route to static markup at build time and inject it into `#root` in `scripts/prerender.ts`. `react-dom/server`'s `renderToStaticMarkup` against the route table already in the file is enough to start; hydrate on the client as now. If a full SSG pass is too large a change, do a stage 2: server-render only the hero, the H1, the intro paragraph and the nav and footer link block for the 10 highest-value routes (`/`, `/pricing`, `/engines`, `/compare`, `/docs`, `/api-docs`, `/about`, `/blogs`, `/reports`, `/audit`). Even that converts 61 empty documents into pages with a heading, a summary and 30 crawlable links.

**Priority.** Critical. Everything else on this page is cheaper to fix, but nothing else changes the fact that the site reads as blank to half the crawlers on the internet.

### T2. JavaScript is never compressed

**Issue.** The gzip middleware skips any response whose content type is not in `COMPRESSIBLE_CONTENT_TYPE_RE`. The pattern lists `application/javascript`. Express 5 and the current `mime-types` database send `text/javascript` for `.js`, so every JavaScript response falls through uncompressed. HTML and CSS match and are compressed, which is why the bug is invisible unless you measure a `.js` file.

**Impact.** High.

**Evidence.** `server/app.ts:63`:

```js
const COMPRESSIBLE_CONTENT_TYPE_RE = /\b(text\/html|text\/css|text\/plain|text\/xml|application\/javascript|application\/json|application\/xml|application\/rss\+xml|image\/svg\+xml)\b/i;
```

Measured against the running production build with `Accept-Encoding: gzip`:

| Asset | Content-Type | Served | Gzipped | Sent |
|---|---|---|---|---|
| `/` (HTML) | `text/html` | 12548 B | 3621 B | gzip ✅ |
| `/assets/index-BEFMryBx.css` | `text/css` | 342 KB | 59 KB | gzip ✅ |
| `/assets/index-CCm918zk.js` | `text/javascript` | 260 KB | 73 KB | raw ❌ |
| `/assets/vendor-firebase-BDXDeNiO.js` | `text/javascript` | 570 KB | 198 KB | raw ❌ |
| `/assets/vendor-react-CoY5GfZZ.js` | `text/javascript` | 243 KB | 90 KB | raw ❌ |

First paint references 18 bundles: **1712 KB raw, 533 KB gzip, 1178 KB avoidable.**

**Fix.** Add `text\/javascript` (and keep `application\/javascript` for older probes). Then assert it in a test so it cannot regress:

```js
expect(COMPRESSIBLE_CONTENT_TYPE_RE.test('text/javascript; charset=utf-8')).toBe(true);
```

**Priority.** Critical. Lowest effort, highest measured gain in this audit.

### T3. Unknown URLs return 200 with the homepage shell

**Issue.** The SPA fallback matches dynamic route prefixes and serves `index.html`, which carries the homepage `<title>`, the homepage description and `canonical = /`. Any string a bot invents under those prefixes becomes a 200 response duplicating the homepage.

**Impact.** High.

**Evidence.** Live checks against `node dist/server.cjs`:

```
/blogs/zzz-not-a-post    200   canonical https://www.catalystlab.tech/    title "CatalystLab — Multi-Dimensional Web Health & Telemetry Platform"
/blog/hello              200   canonical https://www.catalystlab.tech/
/reports/anything        200   canonical https://www.catalystlab.tech/
/playground/x            200   canonical https://www.catalystlab.tech/
/developer/api           200   canonical https://www.catalystlab.tech/
/design-system           200   canonical https://www.catalystlab.tech/   robots "index, follow"
/docs/nope               404   canonical .../404                            (correct)
```

`public/_redirects` makes production worse than local: `/blogs/*`, `/blog/*`, `/reports/*`, `/report/*`, `/playground/*`, `/docs/*`, `/dashboard/*` and `/admin/*` are all rewritten to `/index.html` with a 200, so at the edge a mistyped `/docs/rate-limit` returns the homepage instead of the 404 the Node server would give it.

**Fix.** Three parts. (1) Validate dynamic slugs against real data. `src/data/engineBlogs.ts` holds slugs server-side, so `/blogs/:slug` can 404 for anything not in that set. (2) Delete the `/docs/*` and `/playground/*` rewrites from `_redirects`; every real docs URL is a prerendered file and will win the static match anyway, so the rewrite only catches typos. (3) For routes that must stay client-rendered and unvalidated, return 404 status with the app shell rather than 200.

**Priority.** High.

### T4. The blog cannot be indexed

**Issue.** 10 finished posts exist in `src/data/engineBlogs.ts`, `BlogPostPage` fetches them by slug, and none of them is prerendered, listed in the sitemap, or canonicalised to itself.

**Impact.** High.

**Evidence.** `grep -c "/blogs/" dist/sitemap.xml` returns `0`. `/blogs/optimizing-dom-depth-render-blocking-nextjs` returns the homepage shell with `canonical = /`. The client-side `SEOHead` sets `window.location.href` as canonical after hydration, which means a rendering crawler sees a self-canonical that contradicts the static one. Two canonicals for one URL, one of them pointing at the homepage, resolves in favour of the homepage.

**Fix.** Iterate `ENGINE_SEEDED_BLOGS` in `scripts/prerender.ts`, emit `/blogs/<slug>/index.html` with the post title, description, `og:type=article`, `publishedTime`, `BlogPosting` JSON-LD, and a self-canonical. Add the same 10 URLs to the sitemap with a real `lastmod` from the post's publish date. Firestore posts need a build-time fetch plus a rebuild hook, or a server route that renders on demand.

**Priority.** High. This is the difference between having a blog and having a blog that search engines know exists.

### T5. Sixteen duplicate indexable URLs

**Issue.** Several routes mount the same component under different paths, and each path is prerendered with its own title, its own description and its own self-canonical. Search engines therefore see two or three near-identical pages that each claim to be canonical.

**Impact.** High for cannibalisation, Medium for crawl budget.

**Evidence.** `src/App.tsx`:

```
240-242  /hub, /engines, /services        → DiagnosticHubPage
260-264  /products, /plugins, /integrations → ProductsPage
316,583  /insights, /blogs                → BlogsPage
450,453  /report, /reports                → ReportsDirectoryPage
277-290  /docs/{gitlygase,repo-scanner}   → GitLygaseDoc
         /docs/{ecoholo,eco-audit}        → EcoHoloDoc
         /docs/{vitalzyme,health}         → VitalZymeDoc
         /docs/{edgevmax,latency}         → EdgeVmaxDoc
         /docs/{llm-kinase,llmo}          → AllosterSearchDoc
```

All 16 appear in `dist/sitemap.xml` and all 16 return `robots: index, follow` with a self-canonical.

**Fix.** Choose one path per document and 301 the alias, or serve the alias with `<link rel="canonical" href="primary">` and remove it from the sitemap. The `_redirects` file already has the machinery. Two clean choices per group:

- Engines: keep `/engines`, 301 `/hub` and `/services`.
- Products: keep `/products`, 301 `/plugins` and `/integrations`.
- Blog: keep `/blogs`, 301 `/insights`.
- Reports: keep `/reports`, 301 `/report`.
- Docs: keep the descriptive name (`/docs/vitalzyme`), 301 the generic one (`/docs/health`).

**Priority.** High.

### T6. 570 KB of Firebase is preloaded on marketing pages

**Issue.** Every prerendered page carries the same 17 `modulepreload` tags, including `vendor-firebase` (570 KB raw, 198 KB gzip) and `vendor-motion`. A visitor reading `/pricing` downloads the whole Firebase SDK before the LCP paint, and today it downloads it uncompressed.

**Impact.** Medium-High.

**Evidence.** `dist/pricing/index.html` and `dist/index.html` list identical preload sets: `vendor-firebase-BDXDeNiO.js`, `vendor-react-CoY5GfZZ.js`, `vendor-motion-C5dAN6xx.js`, `page-products-*`, `AuthContext-*`, and 12 more.

**Fix.** Stop preloading Firebase globally. Load it inside the auth guard and dashboard routes with a dynamic import so `modulepreload` follows the route chunk rather than the entry. Removing only `vendor-firebase` from the public shell cuts 198 KB gzip from first paint on 61 routes.

**Priority.** High, and it compounds with T2.

### T7. Titles and H1s disagree, and the homepage H1 targets nothing

**Issue.** The strongest on-page signal on the most important page is a product announcement. The static and client titles differ on at least four routes, so the title changes after hydration.

**Impact.** High.

**Evidence.**

| Route | Prerendered title | Title after hydration | H1 |
|---|---|---|---|
| `/` | CatalystLab — Multi-Dimensional Web Health & Telemetry Platform (67 chars) | Precision Telemetry & Autonomous Web Health Auditing | Meet the all-new Catalyst Telemetry |
| `/engines` | Diagnostic Engines — CatalystLab | Diagnostic Engines Catalog — CatalystLab | (component-rendered) |
| `/compare` | Compare Domains — CatalystLab | Compare two domains — CatalystLab | Compare two domains |
| `/contact` | Contact — CatalystLab | Contact Engineering \| CatalystLab | (component-rendered) |

`src/components/home/HeroSection.tsx:34` is the H1. Its subhead is "More engines. More dimensions. More edge intelligence." Nothing in that block contains "website audit", "SEO audit", "site health" or "telemetry platform", which are the queries the product can realistically win. The homepage description (182 chars, truncated in results) says "Run immediate multi-dimensional audits on any domain", which is a better title than the title.

**Fix.** One H1 and one title per page, derived from the same string, and a query in the H1. For the homepage: H1 "Website health audits across six dimensions", title "Website Health Audit: Six-Dimension Site Analysis | CatalystLab". Have `prerender.ts` read the same constants the page component uses so the two cannot drift.

**Priority.** High.

### T8. Sitemap `lastmod` is the build timestamp on all 61 URLs

**Issue.** `scripts/prerender.ts:485` writes the build date to every `<lastmod>`. On the next deploy all 61 URLs claim to have changed, which teaches Google to ignore the field.

**Impact.** Medium.

**Evidence.** `dist/sitemap.xml` carries `<lastmod>2026-10-23</lastmod>` on all 61 entries, the same date as `generatedAt` in `dist/routes.json`.

**Fix.** Source `lastmod` per route from the real change: the last git commit touching that page, or a `updated` field in the route table that only changes when the copy does. When a URL genuinely has no known change date, omit `<lastmod>` instead of guessing.

**Priority.** Medium.

---

### T9. Five public pages miss the prerender pass

**Issue.** Routes that render real public content fall through to the SPA shell and inherit the homepage canonical.

**Impact.** Medium.

**Evidence.** `dist/routes.json` lists these under `spaRoutes` but not `prerendered`, and they return the homepage shell with `canonical = /`:

```
/docs/orchestrator
/developer/api
```

`/docs/synthshift` was also in that gap and is now correct (`canonical = /docs/synthshift`), so the route table is being maintained by hand and has drifted. `/design-system` is not public content at all and is indexable.

**Fix.** Move `/docs/orchestrator` and `/developer/api` into the prerendered set. Add `/design-system` to `robotsDirectiveFor`'s noindex list and to the 13-route application set, or exclude it from the production build. Add a build-time assertion that every path in `spaRoutes` either has a prerendered file or a `noindex` directive, so drift becomes a failed build instead of an indexed duplicate.

**Priority.** Medium.

### T10. Trailing-slash duplicates serve 200

**Issue.** `/pricing/` and `/pricing/index.html` return 200 with the canonical `/pricing`. Not harmful because the canonical is present, but it doubles the URL surface and splits any link equity that arrives with a trailing slash.

**Impact.** Low.

**Evidence.**

```
/pricing/            200   canonical https://www.catalystlab.tech/pricing
/pricing/index.html  200   canonical https://www.catalystlab.tech/pricing
```

**Fix.** 301 non-canonical forms to the canonical path in `server.ts` and `_redirects`.

**Priority.** Low.

---

### T11. Third-party font CSS blocks the first paint

**Issue.** The Google Fonts stylesheet is a render-blocking request to a third-party origin, after a preconnect but before any paint. On a cold connection that is one extra DNS, TLS and round trip on the critical path.

**Impact.** Low-Medium.

**Evidence.** `dist/index.html` head contains `<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter...&family=JetBrains+Mono...&display=swap">` with preconnects to `fonts.googleapis.com` and `fonts.gstatic.com`.

**Fix.** Self-host the two families as `woff2` in `public/fonts`, subset to Latin, preload the two weights used above the fold, and drop the third-party origins from the CSP's `font-src` and `style-src`.

**Priority.** Low.

---

### T12. The homepage LCP text starts at `opacity: 0`

**Issue.** The H1 is wrapped in a motion element that animates from `opacity: 0`, so the browser paints the largest text block up to 600 ms after hydration.

**Impact.** Medium (LCP).

**Evidence.** `src/components/home/HeroSection.tsx:29-35`:

```jsx
<motion.h1 initial={{ opacity: 0, x: -20 }} animate={{ opacity: 1, x: 0 }}
  transition={{ duration: 0.6, ease: [0.22, 1, 0.36, 1] }}>
```

**Fix.** Animate `y` only, or gate the initial state on `prefers-reduced-motion` and on whether the element is inside the first viewport. Text that is the LCP candidate should not begin invisible.

**Priority.** Medium.

---

### T13. Compression adds no `Vary` when it bails out

**Issue.** When a response is skipped, `Vary: Accept-Encoding` is never set, and it is only added on the compress path.

**Impact.** Low. A shared cache could serve a raw response to a client that advertises gzip.

**Fix.** Set `Vary: Accept-Encoding` at the top of the middleware, before any branch.

**Priority.** Low.

## On-page SEO findings

### O1. Title length and keyword placement

Median title length is **32 characters** across 74 files. The 60-character budget is mostly unused, and several titles are brand-only.

| Route | Current title | Length | Problem |
|---|---|---|---|
| `/` | CatalystLab — Multi-Dimensional Web Health & Telemetry Platform | 67 | Over budget, no query, brand first |
| `/pricing` | Pricing — CatalystLab | 21 | No qualifier, no reason to click |
| `/about` | About — CatalystLab | 19 | Same |
| `/contact` | Contact — CatalystLab | 21 | Same |
| `/legal` | Legal — CatalystLab | 19 | Same |
| `/hub` | Hub — CatalystLab | 17 | "Hub" means nothing to a searcher |

**Fix.** `[primary query] : [reason to click] : [brand]`, keywords first, 50 to 60 characters. For `/pricing`: "Pricing: Six-Dimension Audits From Free to Enterprise | CatalystLab". For `/contact`: "Contact the CatalystLab Engineering Team (24h Reply) | CatalystLab". Drop the em-dash separator for a colon so the words survive truncation.

### O2. Meta descriptions stop short

Median length is **97 characters** against a 150 to 160 target, so most descriptions end mid-sentence in the SERP. The three outliers run long and get truncated.

| Route | Length | Verdict |
|---|---|---|
| `/` | 182 | Truncated |
| `/engines` | 161 | Truncated |
| `/reports` | 52 | Too short to be useful |
| `/plugins` | 78 | Underused |
| `/llmo` | 81 | Underused |

Two descriptions get it right and are worth copying: `/pricing` (143 chars) and `/contact` (133 chars) both state what is on the page and what the reader gets.

### O3. Heading structure

In source, each of the 61 prerendered pages renders exactly one `<h1>`, which is correct. Three files appear to have two, and in each case the two are mutually exclusive branches, so only one reaches the DOM:

- `DomainReportArticlePage.tsx:211` (no report stored) versus `:258` (report found).
- `AdminDashboardPage.tsx:72` (access denied) versus `:170` (dashboard).
- `BlogPostPage.tsx:61` (article not found) versus `:113` (article).

Two structural notes, both material only once T1 is fixed:

- `DocsPage` and the three legal pages render no heading of their own. `/docs` takes its H1 from `DocsLayout.tsx:391`; `Terms`, `Privacy` and `Refund` take theirs from `LegalDocumentView.tsx:116` via `doc.title`. That works today, but the H1 is inherited from a layout or from data rather than written on the page, so a layout refactor or a document retitle can change it without anyone reviewing the heading.
- Until T1 lands, none of this matters to a crawler, because the only H1 in the delivered HTML is "JavaScript is required".

### O4. Internal linking

Source-level link targets cover **34 of 61** prerendered routes. The remaining 27 (`/services`, `/plugins`, `/integrations`, `/llmo`, `/health`, `/repo-scanner`, `/migration`, `/compliance`, `/ai-readiness`, `/legal` and 17 `/docs/*` pages) have no literal link from navigation, footer or body copy. They exist only in the sitemap. Once T1 is fixed, these become genuinely orphaned in the rendered link graph too.

**Fix.** Add a documentation index and a tool index to the footer, and link each `/docs` page from its engine's marketing page and vice versa. Descriptive anchors, not "Learn more".

### O5. Image alt text

In good shape. Source contains 19 `<img>` elements. `PlateImage` (`src/components/common/PlateImage.tsx`) requires `alt: string` in its props and passes it to the `<picture>` fallback `<img>`, which is the pattern used by every marketing page. The one `<img>` without a literal `alt` attribute in the source is inside `src/tests/phase1Hardening.test.tsx`, an XSS fixture, not shipped markup. No action.

## Content findings

### C1. The homepage does not say what the product is

The H1 is "Meet the all-new Catalyst Telemetry", the subhead is a list of comparatives, and the first sentence that explains the offer appears in the meta description and nowhere in the page. A first-time visitor lands on a launch announcement for a product they have never heard of. This is a conversion problem before it is an SEO problem, and it is the single highest-return copy change in the audit.

A replacement that keeps the existing tone:

- **H1:** Website health audits across six dimensions
- **Sub:** VitalZyme, EdgeVmax, GitLygase, EcoHolo, RiskProtease and LLMKinase run in parallel on one domain and return a scored, source-backed report in minutes.

### C2. Ten finished blog posts, zero indexed

`src/data/engineBlogs.ts` contains 10 posts with real slugs and titles, including "Optimizing DOM Depth and Render-Blocking Scripts in Next.js", "Zero-Downtime Platform Migration SEO Parity" and "Generative Engine Optimization and LLM Citations". These are exactly the pages that should be earning long-tail traffic. None is prerendered, none is in the sitemap, and all canonicalise to the homepage. See T4.

### C3. Documentation duplicates split their own authority

Six documents are published twice each (see T5). The two URLs carry different titles, so this is not even a clean duplicate for consolidation purposes. `/docs/health` is titled "VitalZyme: Website Health Engine" and `/docs/vitalzyme` is titled "VitalZyme Engine"; the descriptions differ by the same one word. Both are indexable, both self-canonical, both in the sitemap. Google may keep both and rank neither well.

### C4. Legal and trust pages exist but are weakly linked

`/legal`, `/privacy`, `/terms`, `/cookies` and `/refund` are all prerendered and indexable, and the footer links them through `CANONICAL` constants. Contact information and a physical or jurisdictional address are present on `/contact` and in the legal documents. E-E-A-T signals are adequate. No action beyond the link-level pass in O4.

### C5. Marketing a crawler policy that blocks the audience

`public/robots.txt` blocks GPTBot, ClaudeBot, CCBot, Google-Extended, Bytespider, meta-externalagent and Amazonbot, while the site publishes `/llms.txt` (1603 bytes), `/llms-full.txt` and `/rss.xml` and sells an "AI readiness" engine at `/ai-readiness`. The contradiction is worth a deliberate decision rather than a default. If the product is meant to be cited by answer engines, the same crawlers the site blocks are the ones that would cite it. This is flagged as a decision (recorded as D12) rather than a defect.

## Not measured

The sandbox has no browser, no PageSpeed Insights access and no Search Console, so these were excluded rather than guessed:

- **Core Web Vitals.** No field data and no lab run. The compression finding (T2) is a measured transfer-size fact, not a CWV score.
- **Search Console.** No impressions, CTR, average position, indexing status or manual actions. The "striking distance" analysis in the skill's rankings reference needs this and cannot be run.
- **Backlinks and authority.** No link data.
- **Rendered DOM after hydration.** Client-side titles and canonicals were read from source (`SEOHead.tsx`), not observed. Any statement about what a rendering crawler sees is inferred from code plus the static file.
- **Schema rendering.** JSON-LD is present in every prerendered `<head>` and matches the route, but no Rich Results Test was run.
- **Edge behaviour.** `public/_redirects` and `public/_headers` are Cloudflare-only. The apex-to-www 301, the `.html` redirects, and the `/docs/*` rewrite were read from the file, not observed. Local behaviour was measured against `node dist/server.cjs` and differs from edge behaviour in at least one place (T3).
- **Live crawl.** No external crawl. Everything above comes from the production build in `dist/` plus a local run of that build.
